# Экономика информатизации — решение экзаменационной задачи №6

Репозиторий содержит самостоятельное воспроизводимое решение задачи **«Расчёт TCO и выбор инфраструктурной стратегии»** для компании **«ТехноГос»**, выбирающей инфраструктуру для государственного информационного портала.

Модель сравнивает три варианта размещения системы на горизонте 5 лет:

1. собственный центр обработки данных (**On-premise**);
2. облачный провайдер (**IaaS + PaaS**);
3. гибридная инфраструктура.

Все исходные параметры, ставки, сроки, темпы роста и сценарии чувствительности находятся в JSON. Notebook автоматически строит денежные потоки, дисконтирует их, сравнивает TCO, формирует график и выводит экономическую интерпретацию результатов.

## Что рассчитывается

В работе выполнены все части задания:

- ежегодные денежные потоки по трём стратегиям;
- разовые и ежегодные затраты;
- налог на имущество для вариантов с оборудованием;
- линейная амортизация оборудования за 5 лет;
- номинальный TCO;
- дисконтированный TCO при ставке 12%;
- накопленные дисконтированные затраты;
- точка пересечения затрат On-premise и облака;
- пороговая стоимость облачных услуг, при которой облако сравнялось бы с On-premise;
- график накопленных дисконтированных затрат;
- чувствительность к ставке дисконтирования 8%, 12% и 16%;
- чувствительность к стоимости облачных услуг −20%, 0% и +20%;
- динамический выбор стратегии и управленческая рекомендация;
- пояснения к таблицам и графику, формируемые из расчётных данных.

## Ключевой результат

| Стратегия | Номинальный TCO | Дисконтированный TCO |
|---|---:|---:|
| On-premise ЦОД | 206,18 млн руб. | 176,36 млн руб. |
| Облачный провайдер IaaS + PaaS | 127,91 млн руб. | 93,47 млн руб. |
| Гибридная стратегия | 143,93 млн руб. | 115,85 млн руб. |

По базовым исходным данным минимальный дисконтированный TCO имеет **облачная стратегия**. Она требует наименьших начальных затрат и сохраняет первое место в проверенных сценариях чувствительности.

Точка пересечения накопленных дисконтированных затрат On-premise и облака на пятилетнем горизонте не достигается. При прочих неизменных параметрах базовая стоимость облачных услуг должна вырасти примерно до **37,04 млн руб. в год**, чтобы дисконтированный TCO облака сравнялся с On-premise.

Экономический результат не заменяет проверку допустимости стратегии. Для государственного портала дополнительно необходимо проверить локализацию данных, требования ФЗ-152, безопасность, SLA, резервирование, условия изменения тарифа и возможность выхода из облака.

## Важное методическое решение

Дисконтирование выполнено по формуле:

```text
PV_t = CF_t / (1 + r)^t
```

Год 0 не дисконтируется, год 1 делится на `1 + r`, год 5 — на `(1 + r)^5`. Поэтому в модели не допускается ошибка, при которой последний поток остаётся недисконтированным.

Налог на имущество рассчитан от средней остаточной стоимости оборудования за соответствующий год. При линейной амортизации остаточная стоимость уменьшается, поэтому налоговые платежи также уменьшаются. Налог в год 0 не начисляется.

TCO показывает стоимость владения инфраструктурой. Это не ROI и не NPV инвестиционного проекта: для ROI и NPV потребовались бы данные о будущих выгодах, доходах и денежных притоках.

## Установка и запуск

```bash
git clone https://github.com/Timoshkin-hash/eoi-e6.git
cd eoi-e6
python -m venv .venv
```

Для Git Bash на Windows:

```bash
source .venv/Scripts/activate
```

Для PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

Запуск Jupyter:

```bash
jupyter lab
```

Откройте `notebooks/task_06_tco.ipynb` и выполните ячейки сверху вниз.

Для безинтерактивного воспроизведения:

```bash
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=180 notebooks/task_06_tco.ipynb
```

Для формирования HTML-отчёта:

```bash
python -m jupyter nbconvert --to html --no-input --output-dir reports --output task_06_report notebooks/task_06_tco.ipynb
```

PDF-отчёт в репозиторий не включён: его можно сформировать из HTML через браузер (`Ctrl + P` → «Сохранить как PDF»).

## Как изменить исходные данные

1. Откройте `data/task_06_tco_config.json`.
2. Измените стоимость оборудования, персонала, облачных услуг, темп роста, срок модернизации, ставку налога, горизонт или ставку дисконтирования.
3. Перезапустите Notebook с начала.
4. Все денежные потоки, таблицы, графики и текстовые выводы обновятся автоматически.

Ключевые блоки JSON:

- `on_premise` — параметры собственного ЦОД;
- `cloud` — параметры облачной стратегии и рост облачных услуг;
- `hybrid` — параметры гибридной стратегии;
- `sensitivity` — значения для анализа чувствительности;
- `modeling_choices` — поясняющие настройки налоговой базы и дисконтирования.

## Интерпретация графика и таблиц

Notebook не просто печатает набор чисел. Под таблицами автоматически объясняется:

- где находятся максимальные годовые затраты;
- какие пики вызваны модернизацией;
- какая стратегия имеет минимальный TCO;
- какова экономия относительно ближайшей альтернативы;
- меняется ли лидер при изменении ставки дисконтирования или цены облака;
- пересекаются ли линии накопленных затрат.

Это описание пересчитывается при изменении JSON и не содержит фиксированной рекомендации, привязанной к текущему набору чисел.

## Методические ограничения

TCO не учитывает производительность бизнеса, доходы, качество сервиса и денежные выгоды. Безопасность и регуляторная допустимость также не сводятся к стоимости. Поэтому окончательная рекомендация должна объединять экономические результаты с требованиями к защите данных, SLA, надёжности и управлению поставщиком.
